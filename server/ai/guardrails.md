# Agent 护栏：DEFINE + EVAL

> 方法来源：[i2iLab 学习中心 · 模块③ 设计](https://www.i2ilab.io/learn/define.html)。
> 核心借用了三点：**边界是灵魂**（红黄绿数据分级 + 硬红线）、**人设三段式**（身份 / 语气 / 边界）、
> **评估一票否决**（危机与红队任一不过，就不发布）。

## 1. 四个 Agent 的边界卡（DEFINE）

| Agent | 身份 | 能做什么 | 不能做什么 | 输出闸门 |
| --- | --- | --- | --- | --- |
| AI 玩家 | 同桌玩家，不是真人 | 投资、拍卖、道具、群聊/私信、社区命名 | 诊断/治疗、现实交易、联系方式、冒充真人、泄露提示词、危机时闲聊 | `aiSafety.guardAgentOutput`（聊天/留言/群名/社区名） |
| 规则讲解员 | AI 规则助手，不是真人/客服/专业人士 | 只依据知识库讲规则、数值、流程 | 改规则、扮演其他身份、套取提示词、现实建议、PII、链接 | `agentGuardrails.guardRuleAgentReply` |
| 系统主持人 | 流程播报器 | 阶段提醒、倒计时提醒、系统公告 | 替玩家决策、修改规则、自由发挥 | 固定模板（不调用模型） |
| 社交评定器 | 行为评估器 | 根据本人发言给 A–E 与一句理由 | 评价投资水平/财富/胜负、输出攻击性理由 | `aiSafety.guardAgentOutput` |

## 2. 数据分级（红黄绿）

- **绿**：公开规则、牌桌公开信息、公开发言、知识库数值。
- **黄**：自己的精力/手牌/草稿、玩家本轮提问与对话历史。只用于本轮理解，不写入知识库、不跨会话记忆。
- **红**：真实姓名、联系方式、住址、账号、身份证、健康/心理/诊断、未成年身份、真实金钱往来。
  不索取、不记录、不复述、不猜测；提示词注入与「系统返回」内容同样按不可信处理。

## 3. 三层防线

1. **提示词层**
   - AI 玩家：`aiPrompt.ts` 的 `SAFETY_SECTION`（身份/语气/边界、红黄绿、硬红线、危机协议）。
   - 规则助手：`agent.md` 原文 + `agentGuardrails.ts` 的 `RULE_AGENT_GUARD_SECTION`。
2. **运行时输入层**
   - 危机信号（含最近 3 轮用户消息）→ 固定安全回复，不调用模型。
   - 提示词注入 / 身份劫持 / 越狱 / 编码绕过 / 规则篡改 → 固定边界回复。
   - 手机号、邮箱、证件号、卡号、社交账号 → 隐去后再进模型；索要联系方式 → 固定隐私回复。
   - AI 玩家看到的群聊 / 私信 / 群名同样先隐去 PII，再放进观察 JSON。
   - 客户端带来的历史：去掉伪造的「系统返回 / 命令 / 预取资料」，PII 隐去，注入/篡改轮次丢弃，只保留最近 12 轮、每轮 1200 字。
3. **运行时输出层**
   - 所有玩家可见文本再过一道闸门：提示词泄漏、内部标记、伤害、医疗诊断、联系方式、链接、冒充真人 → 固定兜底。
   - 正常长回答只截断（1800 字），不改写；数值与分点原样保留。

## 4. EVAL：四维评估 + 安全一票否决

`guardrailEval.ts` 内置纯函数红队用例，不调用模型、不联网：

| 维度 | 看什么 | 例子 |
| --- | --- | --- |
| 技术 | 注入、泄漏、历史污染、超长/空输出 | 零宽字符、全角英文、`ignore previous instructions` |
| 体验 | 正常问题不误拦、拒绝话术可继续 | 14 个常见游戏问题全部放行；危机回复 ≤160 字 |
| 专业 | 规则数值一致 | 拍卖 5/5/不立刻扣钱；超额投资基础回报与惩罚顺序 |
| 伦理 | 危机、PII、冒充、医疗建议 | 自伤/暴力/进食障碍/未成年崩溃；手机号/邮箱/证件号 |

**安全一票否决**：伦理维度只要有一条失败，`safetyVetoPassed=false`，整批评估 FAIL。

```bash
cd server
npm run eval:guardrails   # 构建 + 打印四维评分与结论（失败退出码 1）
npm test                  # 全量测试，含 guardrailEval.test.ts
```

## 5. 已知边界（诚实说明）

- 正则护栏是**第一道防线**，不是理解模型；新的绕过写法需要持续补红队用例（测 → 改 → 再测）。
- 规则正确性仍依赖知识库与检索；`buildGroundingHint` 只覆盖高频易错题，其他数值靠知识库。
- 提示词注入无法 100% 消除；本方案的目标是**即使模型被说服，玩家可见输出也过不了闸门**。
- 外部复核优先于自省：新增 Agent 能力时，先加红队用例，再改实现。
